# Blender pipeline

The pipeline turns assets from an already-extracted European Ratchet & Clank (PS4, 2016) release into one portable, validated Blender file per selected model. It is specific to that game and release: it does not extract PKGs and does not support other games or the Rift Apart PC format.

For each model it:

1. indexes the archive and discovers related assets from archive metadata and decoded source references;
2. decodes native geometry, skeleton, skin weights, materials and textures;
3. builds the scene in Blender (materials, the model's own skeleton, persistent Actions, an NLA overview, embedded controls);
4. reopens the saved file in a second Blender process and validates it;
5. promotes the file to its final location, and writes machine-readable reports.

The pipeline renders no images; visual review of the delivered blend is manual, and no automated visual review is performed.

Related documents: [shading](shading.md) (game BRDF, capture facts, lighting), [animation](animation.md) (clip format and baking), [viewer](viewer.md) (the asset viewer, which shares the material reading), [levels](levels.md).

## Running it

Requirements: Windows, Blender 5.0 or newer, and an OptiX-capable GPU for the build process (saved scenes use Cycles on GPU with CPU disabled; the reopen-validation process renders nothing and configures no GPU). The runner itself (`rc2016/pipeline/run.py`) does not import `bpy`; it needs Python 3 with NumPy and starts Blender as a child process. The optional `lz4` package speeds up archive reads; without it the runner logs a `warning` event and prints a warning naming the interpreter (see [Archive loading](#archive-loading-and-caches)).

### PowerShell wrapper

```powershell
.\scripts\run-pipeline.ps1 `
  -ExtractedRoot "<extracted game folder>" `
  -Model "hero_ratchet" `
  -OutputRoot "<output root>" `
  -ImportLOD Highest
```

The wrapper finds the newest `Blender 5.x+` install under `Program Files\Blender Foundation` (or uses `-BlenderPath`), runs `run.py` with that Blender's bundled Python and `-B`, and throws on a nonzero exit code. `-Model` and `-AllModels` are mutually exclusive parameter sets.

### Command line

```text
python rc2016/pipeline/run.py --extracted-root <extracted game folder> --output-root <output root>
    --blender <path to blender.exe> (--model <name-or-path> [--model ...] | --all-models) [options]
python rc2016/pipeline/run.py --extracted-root ... --output-root ... --blender ... --list-models-json <file>
```

`--extracted-root`, `--output-root` and `--blender` are required. Exactly one of `--model`/`--all-models` or `--list-models-json` must be given. The output root must be separate from the extracted root.

## Output root layout

```text
<output root>/
  <ModelName>_<first 8 id chars>/       one folder per model
    <ModelName>.blend                   final, promoted only after reopen validation passes
    meshes/manifest.json                decoded mesh/subset records and reopened value checks
    materials/                          one JSON per material plus manifest.json
    textures/                           only with --export-textures (otherwise cache/t/<model-id>/)
    decoded_sources/manifest.json       per-model links to the shared decoded cache, with hashes
    animation_cache/<animset>/          raw clips and compressed per-clip samples
    reports/                            references.json, limitations.json, ...
    validation/validation.json          fresh-process reopen report
    part_assets/                        material/texture evidence for multipart-character parts
  final/                                source-linked weapon assemblies (see Weapon assemblies)
  variant_assemblies/                   their candidates, receipts, logs and validation
  compressed_assets/  decoded_sources/  hash-addressed shared extraction caches (pruned by default)
  blender/                              candidate and checkpoint blends (pruned by default)
  reports/                              manifest.json, validation_report.json, unresolved_references.json,
                                        unsupported_clips.json, asset_index.json, asset_references.sqlite,
                                        logs/pipeline.jsonl, lighting_inventory.json (novalis only)
  work/                                 job JSONs, pipeline.lock, tmp
  cache/                                textures/ (decoded DDS and transport outcomes) and actor_index/ (kept);
                                        t/ (per-model converted DDS, pruned by default)
```

- The source archive is read-only. Asset IDs, archive occurrences, compressed and decoded hashes, source paths, implementation hashes and final hashes are recorded in the manifests.
- An advisory lock (`work/pipeline.lock`) allows one runner per output root.
- Result statuses: `COMPLETE_MESH_MATERIALS_ANIMATIONS`, `COMPLETE_MESH_ANIMATIONS_MATERIAL_LIMITATION`, `COMPLETE_MESH_ANIMATIONS_TEXTURE_LIMITATION`, `ARMATURE_ANIMATIONS_ONLY`, `UNSUPPORTED`, `FAILED`. A model with present but malformed mesh data is `FAILED`, never downgraded to armature-only. `UNSUPPORTED` means the asset lacks the supported PS4 model sections. `COMPLETE_*` describes delivery coverage, not game accuracy.
- `reports/limitations.json` carries `geometry_game_equivalence`: `structural` (source, counts, topology, round trip) and `semantic_equivalence` (per-subset UV0, normal and tangent claims counted as proven, unproven or unknown). Any unproven interpretation, missing evidence, or `game_accurate_uv_claim: false` keeps `equivalent` false.
- Converted material DDS files use a flat 64-hex SHA-256 name derived from the canonical texture asset path. The pipeline preflights the projected texture path and asks for a shorter output root if it would exceed 240 UTF-16 units.

## Archive loading and caches

`rc2016/formats/archive.py` (`Archive`) reads the extracted release: a folder containing `layout.csv`, `toc`, `dag`, `chunkmap.txt` and the segment files (`locate()` requires exactly one such folder). Container framing follows ig-tools; compressed archive payloads, ALERT outer containers and MSMR/RCRA PC layouts are rejected, not guessed.

- **LZ4.** Raw LZ4 blocks (outer assets, texture streams) use the optional C `lz4` package when it imports. The pure-Python decoder is the fallback (Blender's bundled Python has no `lz4`) and the reference: they decode byte-identically on a 2,044-asset sample covering all 23 asset types plus 150 texture loads, and both reject the same 208 streams. Any C failure or length mismatch falls through to the Python decoder.
- **Layout cache.** The parsed `layout.csv` is pickled to `<repo>/.cache/shared_index/layout_<key>.pickle` (about 60 MB). The key covers the SHA-256 of `layout.csv`, `toc`, `dag`, `chunkmap.txt` and of the parser source (`archive.py`, `common.py`). The cache is ignored if any archive file's presence changed. Layouts under 5,000 entries (test fixtures) are not cached. Delete the pickle to force a re-parse.
- **Decode cache.** `decode()` cache hits compare a `[size, mtime_ns]` stamp stored in `source_mapping.json` (`decoded_stat`, `compressed_stat`) from when the file's SHA-256 was last verified; any difference falls back to the full hash and refreshes the stamp. Source bytes are still read and hashed from the archive every time. `checkpoint()` rewrites `source_mapping.json` only when the mapping changed.
- **Open handles.** Archive files of 16 MB or more stay open per thread; smaller files are opened and closed per read so fixture folders can be deleted. `Archive.close()` releases the calling thread's handles.
- **Asset index.** The archive-wide `assets` table (about 194k rows, about 55 MB) is stored once as `<repo>/.cache/shared_index/assets_<rows-hash>.sqlite`. Each run keeps only its `references_found` table in `reports/asset_references.sqlite`; `reports/asset_index.json` names both. Read them through `rc2016.formats.index.open_asset_index(output_root)`, which exposes both tables and also reads legacy single-file runs; `migrate_legacy_index(output_root)` converts an old run. `write_split_index` reuses the assets table's content hash through `rows_<identity>.txt` (identity = `Archive.layout_identity` plus the `index.py` source hash), and leaves `asset_index.json` and `asset_references.sqlite` untouched when their content is unchanged.
- **Actor index.** The actor reference graph (every actor decoded and scanned once) is stored as `cache/actor_index/<stamp>.json`. The stamp covers `Archive.layout_identity`, the metadata hashes, the `index.py` source hash and the size and mtime of every file in the archive folder; while it matches, later runs load the graph instead of decoding every actor. Each model run still decodes the actors related to it, so their source hashes and decoded files are current.
- **Texture decode cache.** Decoded DDS files and the byte-level part of the texture transport check (header parse, LZ4, deswizzle and DDS comparison) are stored under `cache/textures/`, named by SHA-256 of the built, stream and DDS bytes plus a fingerprint of the decoder sources (`texture.py`, `texture_transport.py`, `archive.py`, `container.py`, `common.py`). Every model and later run of the output root reuses them; source identity, archive-occurrence and stream-hash checks always run. A cached DDS whose bytes no longer match its recorded hash is decoded again. This folder and the actor index are not pruned.
- **GUI scan stamp.** The GUI's `PipelineIndexScanner.scan()` writes `reports/gui_scan_stamp.json`: size and mtime of every file under the extracted root, hashes of `run.py`, `archive.py`, `index.py` and `common.py`, and size and mtime of the index outputs. If everything matches, the previous `gui_model_index.json` is reused without running the CLI; any difference runs it. `scan(reuse=False)` forces a run.

## Native model data

Models are direct PS4 DAT1 model sections (type hash `0x882A03DC`), decoded by `rc2016/formats/native_model.py` with skeleton and inverse binds from `rc2016/formats/skeleton.py`.

- **Positions.** Fixed-point `int16 / 2^shift`, where shift is the u32 at byte 32 of model section `0x283D0383` (default 12, i.e. /4096, when the section is absent). Across all 6,949 archive models this reproduces the mesh-record bounding spheres for every model whose bounds give a clean power-of-two factor (6,711 of 6,711; shifts 3 to 12; about a third of the corpus is not 12). Recorded as `source_units.position_shift`.
- **Vertex record (16 bytes).** Normal at +8 and tangent at +12, each 10:10:10:2 UNORM: three 10-bit fields decoded as `2*(u/1023)-1`, the 2-bit field unused; the vector is renormalized. The format comes from the compiled vertex shader plus numeric agreement, not a captured draw: over 92,353 vertices on seven models both vectors are unit length within 0.0015, the tangent is orthogonal to the normal (median |dot| about 0.0006) and lies a median 0.3 to 0.8 degrees from the UV-derived tangent. The bitangent sign is not stored in +12. The tangent is kept twice on the mesh: raw as `SourceTangentPacked` (INT) and decoded as `SourceTangent` (FLOAT_VECTOR, POINT, native mesh space). Blender's Normal Map node still uses its own UV-derived tangents. Reopen validation compares `SourceTangent` with a fresh decode; blends without it report `decoded_tangent_attribute: absent_pre_tangent_decode_build` instead of failing. Geometry game-equivalence keeps normals and tangents `unproven`.
- **Other records.** Triangle indices; 4- or 8-byte half-float UV0 records (for 8-byte records the second pair is kept as opaque words `SourceUV0SecondaryU/V`, with no UV1 or lightmap meaning assigned; `game_accurate_uv_claim` is false); structurally guarded optional UV1 and colours; 64-byte mesh/subset records; material indices; opaque high mesh flags; four-slot looks; LOD membership.
- **Skinning.** 1-, 2-, 4- and 8-influence `0xDCA379A2` skin batches with normalized weights and strict bounds. Batches whose u32 at +4 and u16 at +8 are nonzero read their u8 ids through a u16 joint palette in section `0x5240C82B` (+4 byte offset, +8 count, palettes packed at 16-byte alignment); five archive models with more than 256 joints use it. The NPC form, a batch with a nonzero +4 and a zero palette count, reads its u8 ids as joint indices plus the +4 value, and fails closed if that exceeds the skeleton's joint count. A nonzero +8 without a palette still fails closed. Models without joints become geometry-only assets.
- **Degenerate triangles.** Triangles with a repeated index or zero area crash or change corner normals in Blender 5.0's custom-normal setter. `native_model.blender_safe_triangles` omits them from the Blender mesh only; vertices and the source index buffer are untouched. Every dropped triangle is listed in the build report (`degenerate_triangles_dropped`), stored on the object (`source_degenerate_triangles_dropped`, `source_triangle_count`) and compared with a fresh decode after reopening.
- **Orientation.** Native Y-up data is kept for validation. Rig and mesh objects get the presentation transform `(x, y, z) -> (x, -z, y)`, recorded on the scene and objects and asserted after reopening.
- **Per-model corrections** live in `rc2016/pipeline/model_profiles/<source-model-sha256>.json`. A profile applies only to that exact source: source hash, mesh count and order, and the ordered raw bound signature must all match before any vertex change; raw signed XYZ is kept as `SourcePositionI16_X/Y/Z` and rechecked after reopening. No profile currently applies a vertex correction (a Blarg Trooper 2x correction is kept under `retired_native_mesh_position_correction` because the decoded position shift supplies the same factor). The bundled profiles select the animation inheritance rule (see below). `--profile` overrides the bundled lookup.
- **Multipart actors.** Actor and config references identify parts. Source-authored `base` parts whose joint hashes are in the actor rig are assembled visibly and skinned to it. Masks, suits, weapon variants and alternates (no `base` token in the name) are listed as identified variants and kept out of the default assembly; undecoded mount and socket rules remain limitations.

## Textures

- Streams: the exact built/stream asset pair is resolved, raw or LZ4 stream bytes are read, the PS4 8x8 block layout is untiled, and a DDS (DX10 header) is written for RGBA8, RG8, R8, BC1, BC2, BC3, BC5, BC6H and BC7, using high-resolution stream top mips when present. The writer emits a single top mip. Header bytes 30 and 32 are read as SD/HD mip counts (bounded by the implied chain length, zero meaning one); extra stream bytes are not serialized as mips because their PS4 layout is not established. The 8x8 block ordering is adapted from MIT-licensed pyswizzle and was checked against an independently converted game DDS.
- Unsupported-in-Blender formats are converted for packing: R8G8_UNORM detail normals decode directly (exact R/G, reconstructed Z, verified row orientation) to a packed PNG, and R8_UNORM likewise; the original DDS and its hash are kept (`conversion_kind` records `DDS_NATIVE_V1`, `R8G8_UNORM_DDS_TO_RGBA8_PNG_V1` or `R8_UNORM_DDS_TO_RGBA8_PNG_V1`).
- All images are packed into the blend with `Alpha Mode: Channel Packed`. Alpha is linear data.
- **Colourspace follows the native DXGI format.** sRGB formats 29, 72, 75, 78, 91, 93, 99 are sRGB; every other format is Non-Color; normals are always Non-Color. In practice `_c` is BC7 sRGB base colour, `_g` is BC7 sRGB coloured specular F0 with gloss in alpha, and `_n` is a DirectX tangent normal.
- **Slot keys.** Texture bindings are resolved by slot key. A material record in section `0xB967FF7A` whose key no referenced graph declares in section `0x1CAFE804` is never sampled; it is dropped and listed in `unbound_texture_references`. Registered families map declared keys to roles (`_c`, `_g`, `_n`, `secondary_normal`).
- **Textures absent from the archive.** A texture with no `layout.csv` entry does not fail the whole material. `classify_absent_texture` records a graph default that the instance overrides for every such slot key under `unbound_texture_references` (status `overridden_graph_default_missing_from_archive`, not sampled). Any other reference goes to the material's `texture_errors` (`missing_from_archive`), which surfaces as `limitations.json` `missing_source_textures` and status `COMPLETE_MESH_ANIMATIONS_TEXTURE_LIMITATION`. No substitute image is applied. The library `textures` list and the transport expectation contain only textures a built material binds; decode-cache leftovers go to `orphaned_decoded_textures`.

### Texture transport gate

Fresh-process validation checks every material texture. `texture_transport_validation.bindings[]` has `source_exact_top_mip=true` only when built/stream identity and bounds are consistent, a raw or LZ4 stream matches the built header size, and a supported top mip deswizzles byte-for-byte to the pipeline DDS. `null` carries an unsupported or missing-stream reason; `false` is contradictory evidence and fails validation. Reopened packed bytes, dimensions, colourspace and `CHANNEL_PACKED` alpha are checked; the PNG adapters record their conversion marker, dimensions and PNG hash. This is transport and packed-image integrity only, with no shader, binding or lower-mip claim.

## Materials and shader translation

Material construction lives in `rc2016/formats/materials.py` (reports) and `rc2016/pipeline/game_shader.py` (Blender node groups); shader analysis is in `rc2016/shaders/`. The shading equations and capture evidence are in [shading](shading.md).

### Opaque base

Opaque surfaces use the **RC PS4 Deferred BRDF** node group from `game_shader.py`:

- diffuse = `_c`; specular = GGX with Schlick Fresnel, F0 = `_g.rgb`, F90 = saturate(60 * F0); roughness = `2^(-2.75 * gloss)` with gloss = `_g.alpha`; diffuse and specular are added, not mixed;
- self-lit = `_c.rgb * _c.a * K`, with K from material key `0x66EFA55B` (per-material values come from the material reports via `emissive_constants_from_reports`);
- metallic stays 0; no invented metallic masks, AO or emission thresholds; UV orientation is preserved;
- glass, energy and other forward-shaded VFX materials are not covered by this group and keep their own recipes.

`game_shader.convert_all()` converts a scene's materials and keeps a fake-user `<name> | pre-RC-game-shader` backup of each; `restore_backups()` swaps them back.

### Preflight, families and translation

Every referenced materialgraph is preflighted before Blender construction, in three layers:

1. **Registered families** (`rc2016/shaders/families.py`). A graph is recognised only when its normalized canonical path and decoded SHA-256 both match an entry. Entries preserve parameter tables, defaults and instance overrides (sections `0x45C4F4C0` and `0xA59F667B`) and report shader stages and support scope. Families: `skin_emissive`, `basic_skin`, `basic_normal_gloss`, `basic_normal_coloredgloss_emissive`, `basic_colored_spec_emmisive_in_c_alpha`, `basic_incandescence` and `character_glass`. They dispatch through `game_shader.apply_preflight_material()`. Their normal-dependent front ends are supported; complete forward skin-ramp lighting is explicitly partial. The `basic_skin` detail-normal blend weight is `0x59011FBD * _g.B`, with the secondary normal at UV0 * `0xB7ABB64A`. The per-writer `_g` channel meanings, the writer decodes and the glass keys were established in the research notes (not included); the code in `families.py` is the reference.
2. **Native translation** (`rc2016/shaders/translator.py`, `bindings.py`, `ir.py`, `nodes.py`, `validation.py`). Supported GCN deferred pixel writers are compiled to a scalar DAG and bound to the material's source pass tables, texture slots and parameter values, with no per-graph recipe, graph-name or shader-ID dispatch (hashes identify bytes only). `prepare_translation` returns `ready` only for one unambiguous source graph whose portable candidates all produce identical source-bound surface expressions; otherwise it returns `unsupported` with diagnostics, including each pixel program's compile failure. BC records partition parameter/resource rows by count, including empty layouts, and their padded CB sizes partition graph-default blocks. Direct descriptors retain their source usage-slot identities. Static indirect resource/sampler tables are admitted only with complete descriptor words, integral aligned offsets, a single proven identity on the active branch, and matching resource/sampler APIs from the source pointer pair. The B6 envelope pointer associates a shader with its BC pass; `source_shader_record` retains the record index, decoded file offset, masks, blob bounds and header pointer. The third B6 word remains uninterpreted. This association does not choose the runtime pass, and material blend/cull flags do not establish that choice. Table indices already include engine slots, so API 5 selects its first material resource. Dynamic indices, partial or mixed descriptors, independent sampler APIs and ambiguous source pointers remain unsupported. Sampler-state interpretation remains a frontend approximation. Candidate comparison preserves texture identity/interpretation, UV expressions, channels, constants and ordered operations while ignoring API/sample/node labels. Receipts retain equivalent candidate sources and `surface_sha256`; rejected variant disagreements retain each candidate's source code hash, pass index, surface hash, per-output structural fingerprints and texture bindings for follow-up; `differing_components` identifies differing ordered source expressions, not numerical disagreement on a sampled texture grid; `translation_sha256` still identifies the emitted program. Equivalence covers only the recovered surface slice: other samples composed into the native normal output are reported as omitted, and runtime variant selection remains unestablished. Forward branches and the exec mask are linearised by predication: a block predicate (uniform branches on `SCC` from `S_CMP(K)` and `S_BITCMP` comparisons and from scalar integer logic and arithmetic (`S_AND/OR/XOR/ANDN2_B32`, shifts, `S_ADD/SUB_[IU]32`, `S_MUL_I32`, `S_ADDK/MULK_I32`, `S_CSELECT_B32`) on constant-buffer words; these are exact 32-bit integer IR ops (`u_*`, `i_*`) on the words' bit patterns, which fold once the material constants are bound and are never emitted by either frontend, so an unbound condition fails closed) and an exec predicate (`V_CMP(X)`, 64-bit mask logic and the `*_SAVEEXEC` forms) are 0/1 DAG values, folded by truth table over their comparison atoms, and every register and export write merges as `select(active, new, old)`. Branches on exec state (`EXECZ`, `EXECNZ`, `SCC` after an exec write or after 64-bit mask logic, as in the kill pattern) are resolved for an active lane inside the tested mask, which assumes scalar values written in an exec-skipped region are not read after it, as in structured compiler output. Writers whose exports are exec-masked (alpha test or discard) are rejected until the discard predicate reaches both frontends. A taken backward branch re-runs its loop body under the taken predicate (bounded unrolling, at most 32 iterations) and merges each iteration's exit, so loops with constant trip counts (scalar counters, or per-lane counters whose exec mask folds to empty) translate; a loop not shown to end within the bound is rejected. A loop diagnostic alone does not identify a missing deferred surface: the rejected loop-bearing Novalis colour-breakup and hill variants export only target 0, whereas their three-target deferred siblings compile. The loop-bearing variants traverse unresolved buffers and are outside the portable deferred-writer contract even if their control flow is translated. Integer VALU (`V_ADD/SUB/SUBREV_I32`, logic, shifts, 24-bit and low multiplies, `V_BFE_U32`, `V_BFI_B32`, integer and byte conversions) and integer `V_CMP` forms use the same exact bit-pattern ops, so they fold when their inputs are bound constants and otherwise fail closed; F32 `V_CMP` also covers the negated forms (`NLT`, `NGE`, ...), which equal plain compares on finite values. Pixel-shader input VGPRs are named from `SPI_PS_INPUT_ADDR`/`ENA` in the stage header (Gnm `ShaderCommonData` followed by `PsStageRegisters`), so reads of screen position, front face and similar appear as unbound `ps.*` inputs rather than uninitialised registers; a layout larger than the program's VGPR allocation is ignored. `FRONT_FACE` is bound when every use is a zero test (integer `EQ/NE`, which the VOP3 table names `LG`): the test becomes `1 - front_facing`, supplied as `gl_FrontFacing` in the viewer and `1 - Backfacing` in Blender, assuming the GCN convention that the input is nonzero for front faces (as in Mesa's radeonsi); the translation records this as a limitation. Other uses stay unbound. Unsupported reachable instructions, loops beyond the bound, forward light loops, branches on unresolved `SCC` (the diagnostic names the instruction that set it) or on lane-varying `VCC` (`S_CBRANCH_VCCZ/VCCNZ` translate as uniform branches when `VCC` depends only on constants, constant-buffer words and values held in scalar registers (one value per wave even when unresolved, except a first-lane check's per-lane substitute); an unresolved condition stays in the predicate, so anything it selects fails closed; a lane-varying `S_CBRANCH_VCCZ` translates only as a skip over a region that begins with `S_AND_SAVEEXEC_B64` on `VCC` before any vector work or `VCC`/`EXEC` write, where lanes without `VCC` are inactive either way), unrecognised engine inputs and conflicting bindings keep the preview fallback. Float VALU coverage includes `V_FLOOR`/`V_FRACT`/`V_CEIL`/`V_TRUNC_F32` (IR `floor`/`fract`, Blender FLOOR/FRACT), `V_MIN3`/`V_MAX3`/`V_MED3_F32`, and the legacy multiply/min/max and clamped `RCP`/`RSQ`/`LOG` variants, which agree with the base opcode for finite values (the IR has no infinities or NaN). `V_RCP_LEGACY`, `V_RSQ_LEGACY`, `V_LOG_LEGACY`, `V_EXP_LEGACY` and `V_RNDNE` stay unsupported. `V_CVT_PKNORM_U16/I16_F32` packs export the clamped values (16-bit quantisation is not modelled, as for `V_CVT_PKRTZ`). A compressed export of a constant register splits the 32-bit word into its two F16 halves, low half first. `python -m rc2016.shaders.census --source <game> --output <report.json> [--materials]` compiles every `.materialgraph` in the archive and ranks the remaining blockers (compile errors, lowering errors and unresolved values with the outputs they block, grouping code offsets and register numbers except for uninitialised registers, whose number names the hardware input) by the number of materials that use the blocked graphs; `--materials` also binds every material and counts its translation diagnostics, splitting binding errors into one reason per failed node with node numbers grouped, and visits materials grouped by graph so the compiled-graph cache is reused. `--jobs N` (default: CPU count, at most 16) runs both phases in worker processes that each open the archive. It also prints the most common PS input address/enable words and, per unsupported material, its complete set of blockers (binding one input unlocks a material only when it is the whole set). Use it to choose the next translator gap. `--show REGEX` (implies `--materials`) reports matching materials in detail, grouped by identical blockers, and traces each blocking interpolant through `rc2016/shaders/interpolants.py`: a pixel program's `attributeN` is its N-th input semantic (2-byte Gnm `PixelInputSemantic`), the vertex program exporting that semantic writes it to parameter slot `EXP 32 + slot`, and that export is compiled with the vertex inputs pre-bound by input semantic (the fetch-subroutine `S_SWAPPC_B64` is skipped), giving its expression, for example a vertex colour passed through. The vertex header is read as Gnm `VsShader` (common data, 7 stage registers, input/export semantic counts at 0x24/0x25, usage slots at 0x28, 4-byte input semantics, then export semantics); the export entry width is accepted only when it reproduces the header's stage size, and the census prints how many vertex headers verify. A failed vertex trace lists the program's first instructions. For shown materials blocked by engine `CB0` words or pixel position, the census also prints the smallest expressions consuming them, as evidence for what those inputs mean. `rc2016/shaders/engine_inputs.py` tests one hypothesis about them: that `CB0[92..107]` hold four corner vectors interpolated as `ray = A + B·y + x·(C + D·y)` over the pixel position and `CB0[28..30]` a camera position, so that `camera + ray·POS_W` is world position. Expressions are expanded into polynomials over named inputs and matched per channel up to a constant factor; the census prints the matched shapes and the engine inputs left after substituting them. The census also runs the experimental world-position adapter (below) on every unsupported material whose blockers include engine inputs and prints how many it turns into previews and what still blocks the others, naming the materials per outcome (`world_position_preview_materials` in the report); shown materials list the outcome per group. A `V_READFIRSTLANE_B32` / `V_CMP_NE` / `S_CBRANCH_VCCZ` wave uniformity check follows its scalar path with the first-lane value equal to the lane's own, which is exact because the other path loops over distinct values to compute the same per-lane result. Unresolved scalar compares name their operands (`S_CMP_LG_U32 of s12=…, 0x0`), and a failed vertex trace lists the ten instructions before the failing one. Vertex traces also follow branches on unresolved scalar compares (per-draw flags such as a buffer word `& 3`) down both paths, merged by `select` on an opaque `runtime_flag@offset` input; this applies to diagnostic traces only, never to translation. For materials the adapter does not unlock, the census prints the smallest engine expressions left after it. `--vertex-colours TEXT` prints, per mesh of up to five model paths containing `TEXT`, its material and colour-stream statistics (min/mean/max per channel, distinct values) plus the model's vertex count over all LODs and its undecoded sections with their sizes in bytes and bytes per vertex (a per-vertex stream divides evenly), and stops; `--colour-material TEXT` keeps only models referencing a material path containing `TEXT` (up to 20) and only their meshes using it, so `--vertex-colours "" --colour-material <ground material>` finds the meshes drawn with a material. `--dump-sections BYTES` also prints the first `BYTES` of each undecoded section as hex and little-endian 32-bit words. `--instances TEXT` prints, for up to eight zones placing models whose path contains `TEXT`, the zone's section sizes and, per matching instance, its undecoded record words from `+0x5C` to `+0xB0` and the start of its tail ([instance record](levels.md#zone-model-instance-table-zone_formatpy)); `--save DIR` (a folder outside the repository) also writes each matching record and its decompressed model as `.bin` files for offline analysis, and stops. `--receipt MATERIAL` prints one material's native and world-position preview receipts (shader, pass, texture bindings, parameters, output expressions, limitations), then the outcome of the viewer's experimental preview for it (pinned or generic), including its error and stops. `--interpolants MATERIAL` prints, for each of the material's graphs, every vertex program's input semantics and exports and, per PS attribute and per setting of the reachable runtime flags, each exported component as a polynomial over vertex inputs, constant-buffer words and opaque atoms (`interpolants.vector_identity`; a normalised export `mul(rsqrt(s), v)` is shown as `v`, with `s` listed), next to the clip-position export for comparison; then, per pixel program, which exports reach each attribute and its smallest consumers. `--attribute N` (repeatable) limits the output to those attributes; up to 10 runtime flags are enumerated, settings that give the same forms are merged and all-zero settings are counted. With more flags, `select` and `max` on flags alone are expanded exactly as 0/1 polynomials and the result is specialised per setting of the (at most 10) flags left outside opaque atoms, within 1,024 terms. The report ends with `bindings.bound_attribute_uses`: per portable pixel program and pass, with this material's constants bound and world position adapted but interpolants left unbound, the outputs each attribute reaches and the largest clamp (`sat`/`min`/`max`) expressions of expanded size up to 200 that use it, such as a blend weight. Unresolved scalar loads print as `mem(s<base>+<byte>)@<instruction offset>`, so the rows of one matrix load stay distinguishable; in the translator every dword of an unresolved multi-dword load is its own unknown, so different words never compare or cancel as equal. This is the evidence for which stream and matrix make an interpolant; normalisation alone does not name it. These traces are diagnostic only; they bind nothing. `prepare_translation(..., world_position=True)` is the explicit experimental adapter built on the hypothesis: after material constants are bound, every expression matching `camera + ray·POS_W` (times a constant) becomes viewer world position (`preview_position`, native Y-up), and the binder then accepts that input. A material that binds this way gets a receipt with `status: experimental`, `preview_contract: world-position-reconstruction-v1`, `automatic_ready: false` and a limitation stating that the engine meaning is inferred; with neither a matched position expression nor proven squared colour inputs it fails. Paint-only writers use the separate `squared-colour-stream-v1` contract and do not enable position or normal substitutions. Both contracts remain experimental. The decoded scalar rock Blend Mask slot may use uniform review value 1 in this mode only when its material row explicitly unsets the texture and the sampled channel is R. `neutral_blend_mask_inputs` records the source API, sample, slot/type identity and review value. This is an explicit preview substitution; runtime null-slot behavior remains unverified. Missing graph defaults, colour textures, other channels and ordinary native binding retain their unresolved-resource diagnostics. In the same mode, a PS attribute is read as the geometry normal (`preview_normal`), recorded as an inferred limitation, only when every vertex program exporting its semantic gives, on every per-draw flag path (flags expanded exactly as 0/1 values), each xyz channel as per-draw words times components of one vertex stream, optionally normalised by an `rsqrt` of the same kind, with no translation: words in stream-free terms must also scale the stream, as in `M·(2s − 1)` (`interpolants.rotated_stream_attributes`). Any other input or opaque operation on any path rejects it, so a camera-relative vector such as `camera − M·p`, a path fetching the vector from another buffer, or a deformed normal keeps the attribute unbound. Normalisation alone is not evidence: a view vector is normalised too. That the stream is the normal and the matrix object-to-world remain inferred. An interpolant channel that every relevant exporting vertex program in the pixel shader's source BC pass can, for some setting of its per-draw flags, fold to `v·v` for vertex input semantic 5 component w (`interpolants.squared_stream_evidence`) is read as the model colour-stream alpha squared (`preview_vertex_alpha_squared`, the viewer's squared vertex alpha; on level instances, zone-keyed vertex colours where present ([levels](levels.md#position-keyed-vertex-colours)), else 1). Nonempty B6 envelope pointers identify the source pass; unknown, duplicate or out-of-bounds joins reject the adapter. Without that table, every graph exporter must agree. Flag proofs are bounded to 12 reachable runtime flags per channel; node folds share only their relevant assignments and skip inactive select branches. Semantic 5 being the colour stream and the active flag path are inferred and recorded as such. Camera-relative `ray·POS_W` and other engine uses still fail closed. Known limits: the writer's geometric-AA gloss term is taken as 1; a native tangent-normal slice is used with Blender's UV tangents (the packed vertex TBN is not reconstructed); texture sampling uses Blender linear filtering and repeat addressing; runtime draw selection is not established. A ready translation is built as `native_translated_deferred_frontend`. The model and level viewers also emit this bound DAG as GLSL through `rc2016/viewer/native_glsl.py`, after fully ported viewer-rule precedence, with a per-viewer Native translation toggle ([viewer](viewer.md#native-translation)). Both frontends retain `game_equivalence: false`; Blender math guards, the optional normal slice and unestablished runtime variant selection remain limitations.
The generic world-position receipt remains a diagnostic surface slice, not a guarantee that it should replace a richer viewer material. The viewer retains a fallback source normal map when inferred geometry-normal inputs affect the preview albedo and no tangent-normal slice was recovered. `census --receipt` includes this suppression as a visible limitation; experimental census counts still count the raw receipts, including suppressed overrides. No source colours, parameters or runtime flags are tuned to match the fallback.

3. **Viewer graph rule** (`materials.viewer_graph_rule`). The asset viewer reads each graph with `rc2016/viewer/textures.py` `material_texture_paths`: the `_g` layout (grey R/G, skin grey cap 0.5, coloured RGB/alpha), specular and gloss scales, the effective self-lit K and mask channel, the exact bound paths, and graph terms (`pick`, `tint`, `spec_tint`, `arch_sequence`, `vehicle`, `glow`, `two_color_metal`, `puddles`, `foliage`, `za_fresnel_power`, `screen`, `rock_blend`, `bng`, `bng_detail`, `facing_glow`, `bright_center`, `bright_glow`, `alpha_cut`) with the viewer's frozen values. The pipeline records this as `viewer_graph_rule` (schema `rcps4-viewer-graph-rule-v2`). A term is `ported` when `game_shader.apply_viewer_graph_rule` builds it and every image it samples is a bound source texture; otherwise it is listed in `unported` with a reason. Forward (glass/VFX) graphs other than `screen` and `bright_glow` are not covered (`applies: false`). Writers listed in `VIEWER_LINEAR_Z_TERMS`, and tint-variant materials, reconstruct normal z as `1 - x*x - y*y` instead of `sqrt(1 - x*x - y*y)`. When an unprofiled, otherwise colour-only material has a fully usable viewer rule it is built with it (`shader_status: viewer_graph_rule_frontend`). Against a ready native translation only an exact graph rule (a `GRAPH_RULES` prefix ending in a dot) with no unported terms other than parallax keeps precedence, so that terms the translation drops (tint, pick, foliage, the normal map) are kept; a battery cannon trim previously came out white. A family-prefix or generic reading yields to a ready translation, as in the viewer (`native_glsl.selected_translation`); `materials.final_shader_status` makes this decision.

Unknown unprofiled graph identities receive a labelled source-colour-only preview (`game_equivalence: false`); `_g` equations and self-lit behaviour are not guessed. Unresolved colour is labelled, not grey.

### Profiles

Model-specific material recipes live in `rc2016/pipeline/material_profiles/<material-sha256>.json` and apply only when the canonical material path and the material's source SHA-256 both match. The profile file and its evidence path are embedded as material properties and asserted after reopening.

- Sheepinator: body (18% body reconstruction, roughness floor, Principled-only colour tuning), thin outer glass (`sheepinator_glass`), and a two-noise transparent energy layer (`wpn_sheepinator_internal_energy`).
- `presentation_tuned` profiles for Combuster: hose (`3d101a87...`), V1 body (`4f7293a0...`), V5 body shell (`32f423bb...`). Texture role, path, DDS hash and colourspace of C, G and N are checked first. Each sets mix 0, unlinks and zeroes C-alpha Principled emission, roughness 0.48, Metallic 0, keeps C base colour and N, and keeps a fake-user factor-1 generic baseline. `game_equivalence: false`.

These profiles predate the deferred BRDF group and are presentation recipes; new work uses the BRDF group and does not reintroduce the `_c * (1 - _g)` mix, Principled-mix recipes, roughness floors or emission thresholds.

### Equivalence labels

Each material report has `material_evidence` (source binding, reproducible recipe, capture/runtime equivalence, unsupported operations), `shader_preflight`, `shader_translation`, `shader_status` and `game_equivalence`. `validated_hash_bound_recipe` means reproducibility only. `game_equivalence: false` or `unproven` means not established, not disproven. The model result repeats this as `material_game_equivalence`. Compiled materialgraph execution, procedural animation, runtime tints and unknown shader parameters remain reported limitations; tuning inferred from a similar name is never promoted.

Fresh-process validation (`rc2016/shaders/validation.py`) asserts, for every polygon-used material, the group's inputs, image colourspaces and packing, parameter values and links through the active Material Output; it never trusts node names.

## Lighting

`--lighting-source` selects one of three sources; the choice is part of the cache fingerprint.

- **`hdri` (default): shared review lighting.** Defined once in `assets/lighting/shared_lighting.json`: HDRI `golden_gate_hills_1k.exr` (a 4x4 box-filtered float copy of a 4k original; same lighting within render noise) turned 45 degrees about Z through a Mapping node (`hdri_rotation_z_degrees`), so models need no rotation for frontal light; world strength 2, no separate lights, view transform Khronos PBR Neutral, look None, exposure -1.0, gamma 1, compositor off. `scene_defaults.apply_shared_lighting` applies it and records it on the scene (`scene["shared_lighting"]`); validators compare against that record, never against hard-coded values. `--lighting-config` selects another file and `--hdri` replaces only the HDRI. The EXR is linked by absolute path, not embedded, so it must stay at the recorded location; a missing EXR fails clearly. Model DDS stay packed. For hand-delivered masters the HDRI can be packed (`pack_scene_images_except_shared_hdri` packs everything else). `scene_defaults.audit_scene()` is a read-only audit and reports `lighting.differs_from_current_shared_file` for scenes built with older lighting.
- **`veldin` (opt-in): captured game look** (`game_look.py`, `game_view_compositor.py`, data in `assets/game_view/`). It sets the captured key light (strength = pi * game light colour), a fitted ambient world, the captured exposure (+2.19 stops) and the "RC PS4 Game" tonemap built as compositor nodes (view transform `Raw`, so no OCIO setup). The key light is placed on the camera's side because the captured direction is relative to the game camera. It is numerically faithful to the capture but washes out on standalone models, so it is not the default.
- **`novalis`: decoded reflection probe.** Uses the validated RefHash-linked reflection asset `0xad76696216314d22` (six 512x512 DXGI 95 BC6H faces). The pipeline PS4-untiles the faces, picks the face orientation that passes every cube-seam test (state `(6,6,6,6,6,6)`, seam ratio about 1.268), samples through the game-to-Blender basis, writes a 1024x512 float EXR, packs it, and uses it as the sole world light at strength 1.0. Source path, hash, face states, seam measurements and EXR hash are embedded and rechecked after reopening. `--novalis-atmosphere-sun` adds the Sun from `atm_novalis.atmosphere` (unit ray at offset 72, RGB96 at offset 96 used directly with no exposure scaling). Only this source runs the light-grid inventory (`lighting.py`, about 60 s per run, written to `reports/lighting_inventory.json`).

Decoded Novalis lighting data (established in the research notes, not included): the day light-grid probe-selector association, the `lighting.zone` tile map (727 entries), the reflection-volume side table, and the atmosphere ray and RGB96. The EUR archive has 21 `volumereflections` probes, 21,158 light-grid assets and 153 local 512x256 BC6H env probes, and no `lightmap` or `irradiance` paths. Not decoded: packed light-grid irradiance words, runtime field names for the RGB96 value, authored light-record semantics, and a world position for a standalone weapon. The `1000` field next to the Novalis ray is not Sun strength.

## Animation in the pipeline

The decoder, container layout and baker are documented in [animation](animation.md). Pipeline behaviour:

- **Default coverage.** Every supported source clip becomes a persistent Action (fake user) on the exact armature. Each model's animsets are found from its actor and model references; unsampled joints use source rest. Unsupported codecs, ambiguous classifications, unrelated clips, path-style root motion and VFX are reported (`unsupported_clips.json`, `limitations.json`), never substituted.
- **Additional clip sources.** Two opt-in sources add rows to the catalog after the referenced animsets; both are part of the fingerprint, their assets join the model's source list (hashed, re-audited before promotion) and `reports/references.json` lists them under `extra_animation_sources`. Each row carries `source_type`, `source_limitation` and `source_provenance`.
  - `--cinematic-clips` scans every `cinematic2` asset for named clips whose joint hashes cover the whole model (`animation_sources.cinematic_sources`) and extracts only those (`source_type: cinematic2`). They are performances from real-time cutscenes in the cutscene's own space, not authored idles; a shot is only as complete as its decode (some version-21 layouts are malformed, see [animation](animation.md#decoder-rules)). This is how NPCs whose animset is an empty stub (the Novalis mayor, Elaris) or who have none (Darla Gratch, Shiv) get motion. Without `--clip` every decoded shot becomes its own Action; `--active-clip` picks the one left active. The same shots can be exported without Blender as a GLB library with a manifest ([animation](animation.md#cutscene-animation-library)).
  - `--borrow-animset <path>` offers an animset that no actor pairs with this model (`source_type: borrowed_matching_rig`). It is accepted only when an actor pairs it with another model whose rest rig `animation_sources.rig_comparison` finds the same: identical parent joints and joint flags, rest translation within 5e-4 of that rig's largest rest translation, quaternion components within 1e-4 and scale within 1e-5 (the rigs the game itself shares animsets between differ by at most about 1e-4 and 2e-6). Joints the anchor lacks stay at rest and are listed. Any other case fails before Blender with every tried model in the message.
- **Selection.** `--clip` selections keep the complete source catalog with original decoder statuses and provenance, plus a separate selection status (`included`, `omitted_by_user_selection`). The delivery is labelled `delivery_complete_animation_library=false` with an explicit enumeration of every clip. Selection is part of the cache fingerprint, so a selected delivery is never reused as a complete library; rebuild without selectors and use `--force`. Fixed-coverage weapon assemblies are skipped in explicit-selection mode, with a logged reason. Selecting one experimental FULL or SSC0 Action keeps both interpretations of its source clip.
- **Channel library.** The baker omits only channels exactly invariant (float32 equality) across source rest and the whole library; a channel that first moves in a later clip backfills constant reset curves into all preceding Actions. Canonical values and the moving-channel mask persist on the rig (`source_channel_library_state`) for checkpoint resume and are checked after reopening. The right SVD factor uses its algebraic unit scale after a rigid-rest guard, and an identity right factor where singular values are equal within `2^-19`; native scale, reflection, collapse and shear stay in the left factor. Source samples and timing are unchanged; derived matrices are held to a `1e-4` tolerance. A 520-clip library remains expensive.
- **NLA overview and controls.** One sequential NLA track holds every Action on a common timeline clock (half-open logical intervals, Blender-safe physical endpoints, mixed frame rates supported; a rate set needing an overview FPS outside 1 to 32767 is rejected rather than resampled), with a scene marker per clip boundary. A catalog and `Animation Controls.py` (`rc2016/pipeline/controls.py`) are embedded as text blocks. Boundaries, held ticks, one-frame clips, markers, selection, Action playback and NLA playback are checked numerically after reopening (see [Reopen validation](#reopen-validation-and-promotion)). Because Blender evaluates the channel domain of every unmuted strip each frame, the full overview of a 520-clip library plays at about 0.12 s per frame; the controls offer a temporary 24-clip range track for fast playback.
- **Cameras.** The review camera is fitted to the visible mesh as evaluated after baking, at the scene's current frame (frame 1 in a new build) with the last baked Action assigned, so a single selected clip is framed at its first frame, using the camera's limiting field of view (joint motion bounds only for mesh-less rigs). Source armatures are saved with ordinary viewport-eye hiding and `hide_render=True`; Actions and modifiers stay active.

### Inheritance rule

Each clip's world pose uses one of two interpretations of the joint-record `+6` bit 0: `full` or `segment_scale_compensation_bit0` (SSC0).

- A hash-bound model profile may fix the rule (bundled profiles do so for Sheepinator and Toxic Crab, with SSC0 evidence in the profile; a profile never chooses a rule for other model hashes).
- A profile may also name `segment_scale_compensation_bit0_after_rotation` (bit-0 joints use the local basis `R * diag(S / parent S)`, the parent scale divided out after the rotation instead of in front of it). It is selectable only by a profile, which `inspect_model` accepts only when the rule fits the model's inverse binds inside the `0.002` tolerance. Across all 539 `character/` models with inverse binds it fits to `1.5e-5` and the bit-0 gating is required (without it seven models fail). It separates itself from default SSC0 only on rigs whose bit-0 joints have a non-uniform parent scale: `npc_sheep` (full `3.1e-3`, SSC0 `2.1e-3`, this rule `3e-7`, confined to three right-arm joints with rest scales about 0.3 percent off unit) and `amb_glow_slug` (SSC0 `1.3e-3`, this rule `1e-6`). Only `npc_sheep` selects it, through its bundled profile; the evidence is rest-pose only, the runtime evaluator is not traced, and the other models keep their existing rule choice.
- Without a profile, if both rules fit the inverse binds and agree within `1e-7` on every sample, the clip uses `full`. If they diverge on animated scale, the clip is included under **SSC0** (`inheritance_basis=pipeline_default_ssc0`, divergence recorded). Basis: the engine's reference-pose builder compensates parent scale only for joints with flag bit 0; Toxic Crab stretchy-IK chains match SSC0; amoeboid bit-0 joints shear to near-degenerate bases (up to 1.0) under `full` but stay orthogonal under SSC0 in most clips. The per-frame runtime evaluator is not traced, and the exact compensation order for non-uniform parent scale is not capture-verified.
- `--experimental-ambiguous-inheritance` additionally bakes both labelled Actions (FULL and SSC0, SSC0 preferred, neither proven) for decoded, source-related clips otherwise blocked by that divergence. Metadata (`experimental_*`) keeps source name, hashes, rate and range, both rules, the divergence, the class and the uncertainty. Each such clip adds two timeline entries.
- Cross-checks: the adapter against `skeleton.worlds(..., 'segment_scale_compensation_bit0')` agrees to `8.5e-14` over 6,924 samples (full inheritance differs by up to `3.65e5`); `T * R * S` fits all ten complete animated pairs' inverse binds within `2.7e-6` (a compatible convention, not unique engine semantics).
- Clips with no matching joint hash are `unrelated`. A clip whose translation/rest-length ratio is neither near 0 nor near 1 is `unsupported` unless a profile override names its class.

The Proton stage produces a separate blend with mix 0.18, `_g` RGB saturation 2 on the Principled specular-tint input only, and view Khronos PBR Neutral / None / exposure -0.5 (a per-model presentation default, not a shader rule). Its receipt pins the native blend and receipt hashes, the profile and reference hashes, the scripts, the source model IDs and hashes, polygon-used material identity and the C/G/N transport identities, and a cache hit also checks final and report hashes, the `presentation_tuned` / `game_equivalence=false` labels and the V1/V5 PNG hashes. An identity mismatch fails only the optional presentation delivery. The native assembly is untouched.

## Reopen validation and promotion

Every build writes a candidate under `blender/`, which a second Blender process reopens and validates; only then is it promoted (`common.promote`) to the model folder. Replacing an existing final requires `--force`. Before promotion the runner confirms that no source changed during the build: when every file in the archive folder keeps the size and mtime it had when the run started and every related source was hashed during this run with its recorded hash, nothing is re-read; otherwise every related source asset and the archive metadata are re-read and re-hashed.

Validation checks mesh, material and image presence; source hashes; packed images and the texture transport gate; normalized in-range skin weights; native geometry round trip and the degenerate-triangle record; material wiring per polygon-used material; scene defaults saved in the file (Cycles GPU device and OptiX denoiser, perspective camera, transparent RGBA film, 96 samples and the other render defaults; the process-level OptiX device selection is not checked because nothing is rendered); shared-lighting record; the upright presentation transform; Actions, slots, markers and NLA strips. Geometry, UV, tangent, raw-word and material-slot comparisons read Blender data in bulk (`foreach_get`); vertex-group memberships are read per vertex.

Animation (matrix error tolerance `1e-4`, `rc2016/pipeline/bulk_checks.py`):

- every clip's raw bytes and sample hash are re-decoded, and the cached sample file must hold exactly the freshly decoded frames (serialized-text comparison);
- every key of every F-curve is read (`foreach_get`) and must use CONSTANT interpolation; the pose those keys define at every source frame is composed in numpy from the bake rig's rest matrices (helper root plus bone, full inheritance, local location, quaternion channels; asserted on the rig) and compared with the source matrices (`keyframe_max_matrix_error`);
- Blender's own evaluation is checked on sampled frames per clip: first, middle, last and the frame of largest motion (plus the pinned deformation-probe frame), through the selected Action (`action_evaluated_frames`) and, after one switch to the NLA overview, the same samples on the timeline plus each strip's held final tick (`nla_evaluated_frames`);
- `jump_to` is exercised on the first, middle and last clip; markers and strip boundaries are checked for every clip; the rest pose is evaluated once.

Scene defaults come from `rc2016/pipeline/scene_defaults.py` (`apply_new_scene_defaults`, `audit_scene`): 3840 x 2560 at 100% (new builds then apply the render size rule below), PNG RGBA at 100% compression, transparent film, adaptive sampling with denoising, 96 samples (32 viewport preview), adaptive threshold 0.04, 5 total bounces (2 diffuse, 2 glossy, 4 transmission, 6 transparent, 0 volume), Light Tree, Persistent Data.

New scene builds use the reference orientation (`CAMERA_EULER_DEGREES`), a 50 mm perspective lens and `frame_camera_zoom` to fill 1/1.10 of the frame on the longer screen axis. `fit_render_region` enables Crop to Render Region and fits the visible evaluated mesh with 10% padding on the longer screen axis and 7% on the shorter, raised to at least 25% horizontally so the crop leaves space beside the model. Camera rotation stays fixed while the camera moves to fit and centre the model. Mesh-less diagnostic rigs retain the full frame and the joint-fitted camera, with the fallback recorded in the embedded Render Region receipt.

### Render size

Textures smaller than the frame resolution look soft at full size: the game caps some character assets (for example Cora's body) at 1024 px while her head and eyes use 2048 px. After the camera and Render Region are fitted, `fit_render_size` sets `render.resolution_percentage` from the texel density of what the camera sees; `resolution_x`/`resolution_y` and the crop fractions never change, so a render is the same picture at a smaller pixel size.

- **Metric.** For every front-facing triangle of the visible evaluated meshes at the current frame (`obj.hide_render` meshes excluded; vertices as deformed by the armature) that is not hidden behind other geometry (a ray from the camera to its centroid must reach it first; at most 40000 triangles are tested, taken at an even stride), the linear density is `sqrt(UV0 area x width x height / projected pixel area)`: base-colour texels along one render pixel at 100% size. The width and height come from the material's `_c` image (the same node choice as the game shader conversion). Triangles whose material has no `_c` image, or only a placeholder of 4 px or less, are skipped. The metric is the **median weighted by projected screen area**, so the surfaces that cover most of the character decide the size and tiny high-density parts (eyes, eyelashes, beards) cannot. A plain triangle-count median would follow vertex density instead, and a mean would follow those small parts.
- **Percentage.** `ceil(100 x metric)` clamped to 25..100 (`render_percentage_for_density`). A metric of 1 or more, or a model with no textured visible mesh, stays at 100; the rule never upscales. At the chosen size the median surface sits at about one texel per pixel (`metric x 100 / percentage`), and at most half of the screen area is below it.
- **Receipt.** The builder stores the result as `render_size` inside the embedded `Render region.json` text: `status` (`scaled`, `scaled_to_minimum`, `full_size_texel_density_at_least_1` or `full_size_no_textured_mesh`), `resolution_percentage`, the metric at 100%, the density after scaling, the triangle counts and the per-material screen share and median density (largest twelve).
- **Validation.** `audit_scene` expects 3840 x 2560 at 100% unless that receipt records a percentage, in which case the scene must carry exactly that integer (25..100). A malformed record never matches. Scenes without a `render_size` record (older builds, weapon scenes) are still expected at 100%.

The density is a resolution heuristic, not game data: it ignores the screen-space filtering, mip selection and detail normal maps of the game renderer, and treats UV0 as the base-colour mapping.

## Cache reuse and the implementation hash

The runner hashes every `.py` file under `rc2016/formats`, `rc2016/shaders` and `rc2016/pipeline` (weapons included), plus `rc2016/common.py`, `rc2016/viewer/textures.py` (the viewer's per-graph material reading), `third_party/opengnm/gcn_types.h`, `rc2016/pipeline/material_flags.json.gz`, and every JSON in `model_profiles` and `material_profiles`. The per-file hashes are stored as `implementation_sha256` in `reports/manifest.json`; their combined hash is the code term of each model's fingerprint.

The model fingerprint also covers archive metadata hashes, the model profile, source asset hashes, built and stream texture hashes, import LOD, `--export-textures`, `--experimental-ambiguous-inheritance`, the clip selection identity, the lighting identity (probe and face hashes for Novalis; the capture-data and script hashes for Veldin; the HDRI hash plus shared-lighting settings otherwise) and the Blender path.

`--reuse-cache` accepts an existing final only if its recorded fingerprint, file hash and validation report still match (and any preview image hashes an older report recorded). If only variant-assembly orchestration code changed, an existing complete-library model delivery is reused after its source dependencies are re-audited (`reused_source_audited_delivery`). Otherwise the runner refuses to overwrite without `--force`. Log events (`reused_verified_delivery`, `*_assembly_reused`) are in `reports/logs/pipeline.jsonl`.

## Known limitations

- Material appearance is a Blender reconstruction. Compiled materialgraph execution, runtime layer composition, procedural animation, runtime tints and unknown shader parameters are not reproduced; `game_equivalence` is never claimed. Glass, energy and VFX materials are forward-shaded and covered only by their documented recipes.
- Geometry: UV0 meaning for 8-byte UV records, and normal and tangent interpretation, are unproven. The bitangent sign is not stored.
- Textures: one mip level only.
- Animation: only the PS4 version-15 sample layout (clip versions 15 and 21) is supported. Runtime scale-compensation flags, additive animation graphs, path/root-motion sections, timing flags and subframe interpolation are unproven or unsupported. Relative/additive clips are standalone previews (rest T + delta T, rest Q * delta Q, rest S * delta S) because the blend partner and weight are unknown.
- Lighting: no runtime light data (light-grid irradiance words, authored light records) beyond what is listed above is decoded.
- Weapon assemblies pin specific asset IDs and hashes; they apply only to those exact sources, and actor weapon selection and attachment transforms are not decoded.
- The Pyrocitor gold presentation stage loads its pinned canonical scene and HDRI from the private research workspace, so it needs `RC2016_RESEARCH`; both files are hash-checked.
